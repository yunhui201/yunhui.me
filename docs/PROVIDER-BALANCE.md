# 供应商余额与额度

「我的供应商」卡片显示上游返回的余额、币种和上次成功查询时间。进入页面时自动读取，页面可见时每五分钟刷新；支持刷新全部供应商、单家供应商或单个 Key。多个 Key 可能属于同一账户，因此分别显示、不累计；其他 Key 的明细默认折叠。

添加供应商后默认自动识别已适配的官方域名。自建中转可在「编辑供应商 → 余额查询」选择接口类型。手机伴侣的供应商页面也可查看及手动刷新，查询配置在电脑端管理。

| 类型 | 查询接口 | 显示含义 |
| --- | --- | --- |
| 云汇 / Sub2API | `GET /v1/usage` | 根据响应区分账户钱包、API Key 总额度/周期额度、订阅每日/每周/每月额度 |
| DeepSeek | `GET /user/balance` | 每种币种的钱包余额，保留真实零余额和欠费 |
| Moonshot / Kimi | `GET /v1/users/me/balance` | 中国站 CNY、国际站 USD 的可用余额 |
| OpenRouter | `GET /api/v1/credits` | 总充值减总使用；密钥需具备此接口的查询权限 |
| 阶跃星辰 | `GET /v1/accounts` | CNY 余额 |
| Novita | `GET /openapi/v1/billing/balance/detail` | `availableBalance` 按万分之一美元转换 |
| New API 兼容接口 | `GET /api/usage/token/`，公开 `GET /api/status` | 令牌额度；仅接口明确返回用户额度时显示账户余额 |

自动识别只匹配已确认的完整主机名，不根据供应商显示名称猜测。其他 Sub2API/New API 域名需要手动选择对应类型，部署在子路径时保留路径前缀。旧 One API 版本未必提供相同接口，不承诺通用兼容。

New API 必须从站点的公开元数据确认单位和换算参数；缺少信息时显示“额度点数”，不假定为美元。旧版兼容计费接口的单位和额度范围可能受站点配置影响，因此不自动将其金额认定为钱包余额。没有可验证接口的服务显示不支持或可配置自定义查询，不伪造零余额。

## 自定义接口

选择「自定义查询」，按服务商文档填写完整地址、GET/POST、认证方式以及 JSON 字段路径。支持余额字段，或同时填写总额与已用字段自动相减；可选择账户余额、密钥额度或套餐额度，并填写币种与换算倍率。字段路径支持对象与数组，例如 `data.balance`、`wallets[0].amount`，不执行脚本。

同源接口可以复用每个已启用的 API Key；另一个站点的查询使用独立查询 Token 或无需认证。独立认证不会继承模型接口的认证头。可配置认证头、Bearer/原始格式、附加请求头和静态 JSON 请求体。公网请求使用 HTTPS，回环开发服务可使用 HTTP；不跟随重定向。

配置保存后生效。停用供应商、关闭余额查询或没有可用凭据时，不请求接口。余额查询不会调用聊天接口，也不写入本地对话用量或账单估算。

## 缓存与失败

成功结果缓存五分钟，失败短暂缓存，手动刷新也有十秒防重复间隔；相同查询合并，最多同时查询三个 Key。单次请求包含响应体读取在内限时十五秒、响应体最多 1 MiB。

查询失败时保留上次成功余额并明确标记，时间不更新为“成功”。更换地址、密钥、代理或查询配置后，旧结果失效，迟到响应不会恢复已删除的供应商。缓存单独保存在 `provider-balances.json`，不修改供应商配置的更新时间，不参与路由额度或费用估算。

查询 Token 留在电脑端；网关返回标准化金额，不返回查询地址、请求体或认证凭据。配置备份延续原有“包含密钥”的语义，需要妥善保存。

## 本地验证

- 余额后端 20 项：官方端点、单位、零/负/缺失余额、范围区分、多 Key、缓存并发、改配置与删除竞态、超时、响应限制、认证和缓存失败。
- 桌面余额界面 8 项、原供应商同步界面 7 项：折叠明细、自动/手动刷新、旧值保护、配置保存及失败恢复。
- 客户端配置 35 项、网关 48 项、模型同步 6 项、本地客户端导入 20 项回归通过。
- 手机接口 6 项、手机浏览器流程 25 项通过，包含余额显示、失败保留及禁用保护。
- 实际 Electron、preload、动作层、HTTP 网关与本地模拟余额服务的 7 项连通验证通过；余额查询未增加本地计费记录。

这些测试使用隔离目录和模拟余额服务，不读取或改写真实客户端配置，也不向生产账户发起计费请求。生产供应商的权限、站点定制和接口可用性仍以实际查询结果为准。
