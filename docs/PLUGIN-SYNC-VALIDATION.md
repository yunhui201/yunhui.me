# 插件市场同步修复 · 2026-11-15

点击「同步市场索引」时，旧实现只访问 GitHub raw 下载地址。该地址在本机网络无法建立连接，45 秒后抛出英文超时；同步未采用应用内代理，两个市场顺序执行，界面还把同步失败的重试错误地指向桌面客户端检测。

## 修复

- 下载采用系统设置中的 HTTP(S) 代理；原始地址阻塞时启动同一 GitHub 仓库的 API 备用请求。所有来源仍校验仓库、路径、目录结构与大小，不跟随外部下载链接。
- 通过远端文件 SHA 与已校验的本地内容比较，未变化时无需再次下载完整索引。缓存保存原始文件 SHA 和内容摘要，修改过的缓存不能误报为远端最新。小文件复用 API 返回的 Base64 内容，大文件按 raw 媒体类型下载并校验 SHA。
- 两个市场独立同步，同一目录、同一来源的并发请求合并。失效响应不写入缓存，磁盘保存失败不触发重复下载。
- 原始地址最多等待 8 秒；备用请求通常在 1 秒后启动，原始请求提早失败则立即启动。完整同步含正文传输最多 120 秒，仅对应的桌面桥接刷新请求延长至 130 秒。
- 界面分别显示远端核对成功、本地缓存和随附离线目录；部分失败不提示全部成功。重试保留原同步范围，连续点击不会重复发送。列表刷新错误和桌面连接错误独立显示。
- 原生桌面市场通过其实际读取的 `message` 与 `cached` 字段显示失败原因，并保留可用插件。
