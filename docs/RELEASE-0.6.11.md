# 云汇 AI · yunhui.me 0.6.11

[下载本版](https://github.com/yunhui201/yunhui.me/releases/tag/v0.6.11) · [安装说明](../INSTALLATION.md) · [使用指南](../USER-GUIDE.md)

本版修复旧会话提示供应商不存在，以及自动迁移后仍请求旧模型而无法续聊的问题。云汇会补齐可识别的历史供应商入口，并让自动修复的会话通过兼容连接使用本次选择的供应商和模型。

- 兼容历史中出现的供应商名称，减少打开旧会话时提示供应商未定义的问题。自动整理后的会话使用独立兼容入口，避免历史里保存的旧模型绕过本次选择。
- 网关或官方账号共存模式下，自动修复的会话使用独立的历史兼容连接。桌面端重启后打开旧对话，即使记录仍保留旧模型名，也会请求当前选择的供应商和模型。新建对话仍按客户端的模型选择使用。
- Codex CLI 的 **复制恢复命令** 会自动携带会话实际使用的供应商，避免默认供应商变化后无法恢复；支持 Windows PowerShell 和 macOS 终端。
- 直连模式使用当前接口和密钥，旧会话的模型名仍需上游支持。
- 供应商不存在、被禁用或没有可用密钥时明确报错；官方账号凭据与第三方服务保持分开。
- 延续“先保存配置，再单独处理历史”的流程。客户端运行中或历史处理失败，不撤销已经保存的新配置。

## 升级后怎么操作

1. 在 **客户端接入** 选择可用的供应商和模型，点击 **预览配置**。
2. 点击 **保存配置**，确认显示 **配置已保存，重启客户端后生效**。
3. 查看历史处理结果。若显示待处理，保存工作并退出相关客户端后，再次保存配置以尝试自动修复。历史暂时无法处理不影响新配置使用。
4. 重新启动桌面客户端并打开旧会话。要用 Codex CLI 续聊，在云汇 **历史会话** 中选择记录，点击 **复制恢复命令**，Windows 粘贴到 PowerShell，macOS 粘贴到终端。
5. 网关或共存模式使用期间保持云汇运行；直连旧会话能否继续，取决于上游是否支持其原模型。

历史兼容配置不会找回已经缺失的聊天正文，也不能保证其他账号或供应商的加密内容能够续用。出现上游权限、余额或模型不可用提示时，按实际接口错误处理。

## 下载与升级

Windows 提供安装版、免安装版与完整 ZIP；macOS 提供 Apple Silicon 和 Intel 的 DMG / ZIP。升级前退出云汇并保留原数据。ZIP 版完整解压后运行 `YunHuiAI.exe`；Mac 将 `YunHuiAI.app` 放入“应用程序”并替换旧应用。

macOS 包尚未签名与公证。确认来自项目发布页后，若首次打开提示“已损坏”，在终端运行：

```bash
xattr -cr "/Applications/YunHuiAI.app"
```

应用内更新优先使用 GitHub，官网为备用下载来源。
