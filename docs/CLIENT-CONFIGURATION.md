# 客户端配置目录与接入流程

本文说明当前源码的客户端配置流程。[下载客户端](https://github.com/yunhui201/yunhui.me/releases/latest) · [安装说明](../INSTALLATION.md) · [使用指南](../USER-GUIDE.md)

ChatGPT 桌面入口通过 `config.toml` 配置客户端使用的接口地址、认证和模型。程序安装位置与配置目录分别识别；找不到 `.exe` 或 `.app` 不阻止配置预览和保存。

| 用途 | Windows | macOS |
| --- | --- | --- |
| Codex 共享配置 | `%USERPROFILE%\.codex\config.toml` | `~/.codex/config.toml` |
| 原客户端登录文件 | `%USERPROFILE%\.codex\auth.json` | `~/.codex/auth.json` |
| 自定义 Codex 配置目录 | 已设置 `CODEX_HOME` 时使用其中的 `config.toml` | 同左 |
| Claude Code 用户配置 | `%USERPROFILE%\.claude\settings.json`，遵循 `CLAUDE_CONFIG_DIR` | `~/.claude/settings.json`，遵循 `CLAUDE_CONFIG_DIR` |
| Gemini CLI | `%USERPROFILE%\.gemini\settings.json` 与 `.env` | `~/.gemini/settings.json` 与 `.env` |

向导显示本次实际使用的配置路径。Claude 桌面版另用系统对应的应用数据目录与 `Claude-3p/configLibrary`，不套用 Claude Code 路径；多目录有冲突时先确认位置。

## 配置流程

1. 选择客户端、供应商和模型。运行时发现的本地 API 配置会导入供应商列表；官方 OAuth 登录记录单独识别。
2. 在“共享编程配置”查看实际路径。已有文件会标为“已发现配置”，首次配置会标为“应用时创建”。
3. 选择接入方式，预览实际文件路径和脱敏差异，点击“保存配置”。原配置会先备份；客户端正在运行或历史存在问题均不影响保存配置。
4. 查看“配置已保存”结果，再保存工作并重新启动读取这份配置的客户端。需要云汇一键重启或桌面增强时，展开“程序识别”，重新检测或选择 Windows 主程序/macOS `.app`。选择程序不会自动应用配置；更换程序会断开已有增强连接。
5. 需要撤销时使用“恢复原配置”。桌面入口和 CLI 共用同一份配置与首次备份，修改和恢复状态同步。历史处理会单独尝试，结果可按需展开。

同一份配置可以由 Codex CLI 和读取 Codex 配置的桌面版本使用。重启后客户端根据选中的 `model_provider`，使用对应供应商表的 `base_url`、`experimental_bearer_token` 和模型发送请求。桌面版本识别与配置保存分开检查，尚未识别的版本不能仅凭保存成功认定已经完成运行验证。

## 配置保存与历史处理

应用、重新应用和恢复原配置时，先完成配置文件与连接记录的保存，再独立尝试处理历史。历史处理不是保存配置的前提；正在运行的客户端不会被强行结束。

客户端已退出且历史可处理时，会完整备份当前目录的会话日志与历史索引，再修复可处理记录；损坏、重复和路径无法确认的历史原样保留。客户端仍在运行、历史被占用或无法备份时，本次历史处理暂缓或显示未完成，新配置仍保留。需要时可稍后在历史页面单独整理。

配置自身的备份、写入或连接记录保存失败时，会报告配置失败并尝试撤销本次配置修改。历史处理失败不会撤销已保存的配置，也不会显示为已完成备份或修复。其他程序产生的配置改动会保留；配置发生变化时重新预览确认即可。

恢复原配置会保留目前已有的对话正文和新建会话，只衔接到原配置的供应商区域。聊天正文、归档状态、父子任务关系和加密字段不因归属迁移改变；加密上下文的账号或供应商限制仍然存在，不能承诺跨服务续聊。范围与独立修复方法见[历史迁移指南](HISTORY-PROVIDER-MIGRATION.md)。

## 接口地址与密钥如何生效

| 接入方式 | 写入客户端的地址和密钥 | 请求路径 |
| --- | --- | --- |
| 云汇网关 | 本机网关地址、云汇访问令牌 | 客户端 → 云汇 → 所选供应商；云汇向供应商发送该供应商的 API Key 和原始模型 ID |
| 供应商直连 | 供应商 API 地址、供应商 API Key | 客户端 → 供应商；不依赖云汇网关运行 |

默认使用云汇网关，可转换协议、记录用量并应用网关功能。直连要求客户端与供应商的协议一致，且客户端适配器能够表达所需参数。供应商设置了自定义请求头或代理等需要网关处理的选项时，应使用云汇网关。官方账号与第三方模型共存也使用网关。

普通 API 模式写入 `model_provider = "yunhui"`，并更新 `[model_providers.yunhui]` 下的地址、Bearer 密钥与 Responses 协议。已有活动 profile 中的同名供应商覆盖会同步更新；其他供应商和 profile 保留。若同名供应商存在不兼容的 `auth` 或 `aws` 认证配置，预览会说明冲突并停止应用。新版 CLI 单独的 `--profile` 配置文件仍可能覆盖用户级设置，应确认客户端实际启动参数。

可读取的旧会话仍引用已缺失供应商时，会补充对应的兼容入口。网关模式将其请求绑定到此次选择的供应商与模型；直连使用所选服务的地址和密钥。已有独立供应商配置和官方内置供应商保留，官方登录文件不变；历史整理未完成也不影响配置保存。保存后重启原客户端加载补充的入口。

旧版配置继续兼容本地识别和插件模型目录；重新应用 API 配置时使用 `yunhui`，旧供应商表保留，恢复仍可回到首次接入前的原文件。保存后会尝试备份并迁移旧区域历史；“历史会话 → 批量修复历史 / 区域迁移”可独立整理指定范围或处理暂缓的历史。官方账号共存通常使用客户端内置的 `openai` 标识，实际迁移目标以本次预览为准。

## 官方账号与 API 模式

普通 API 模式写入独立供应商及其 Bearer 令牌，不改写 `auth.json`。某些桌面版本可能因此暂时隐藏官方聊天或云功能；保留登录文件与保留界面中的官方身份呈现是不同的行为。

需要同时使用官方账号与第三方模型时，选择“保留官方账号并与第三方模型共存”。此模式需要有效的本机官方登录和模型目录；官方请求与第三方请求使用分开的认证。详情见 [官方账号共存](CODEX-COEXISTENCE.md)。

## 确认配置已生效

应用成功后重新打开客户端，选择配置中的模型并发起一条对话。网关模式可在云汇查看对应请求；直连模式请在客户端与供应商侧核对。若仍使用旧服务，检查原客户端的项目级配置、启动参数或环境变量是否覆盖了向导显示的文件。

Windows 和 macOS 均可先保存配置，再重启客户端。退出要求只适用于改写历史等需要独占文件的操作，不是保存客户端配置的前提。
