# 模型上下文设置

供应商编辑器中的上下文支持逐行输入和批量修改。原批量入口依赖桌面运行环境不支持的浏览器 `prompt()`，现改为应用内面板，明确选择模型范围、仅填空或覆盖已有值。输入采用字符串草稿，失焦和保存时校验正整数，避免输入中途转换数字；出错会保留草稿。

GPT / Codex 文本模型没有容量数据时推荐 `272000` tokens。已有上游或手动填写的明确数值会保留；图像、语音、嵌入、辅助模型和其他厂商模型不自动套用。此建议不会增加上游实际容量。上下文留空时，已识别文本模型保存为推荐值，其他模型保持未设置；价格留空仍表示未知，价格 `0` 才表示已确认免费。

模型管理页可选择当前筛选结果中的 ChatGPT 文本模型，再批量编辑并预览。单模型编辑带出当前窗口；混合选择不会启用 ChatGPT 专用推荐值按钮。同步不会覆盖手动设置的窗口，批量保存和导入也会验证正整数。

保存后，已接入的 ChatGPT / Codex 需要重新预览、应用配置并重启。普通 API 模式同时写入用户级 `model_context_window` 和 `model_auto_compact_token_limit`，后者按窗口的 **90%** 向下取整（至少 1 Token）。每次应用新的上下文都会重新计算，替换旧的固定 Token 阈值。两个字段一起备份和写入，恢复连接可还原原始配置。

共存模式把窗口与 90% 阈值分别写入每个模型的目录项，并清除配置中旧的全局窗口/阈值覆盖，避免所有模型沿用同一份数值。当前旧 profile 中的同名覆盖也会清理，不新增旧 schema 不支持的字段。目录更新后仍需重新应用并重启客户端。

在“桌面增强 → 高级设置”直接设置上下文时，两个字段同次保存；清空上下文则一起恢复原生默认。压缩阈值仍可单独手动填写，但下一次设置上下文会重新按 90% 计算。单模型和批量编辑界面会显示计算后的阈值。

## 上下文与压缩

默认联动规则如下，不再乘一次有效预算比例：

| 设置的上下文 | 自动压缩触发阈值（90%） |
| ---: | ---: |
| 272000 | 244800 |
| 200000 | 180000 |
| 128000 | 115200 |

90% 表示何时触发，不是压缩后保留多少内容。客户端的 95% 有效预算是另一个设置，不参与云汇这次阈值计算。已有的统计范围和回合结束压缩策略保持原值；显式配置了这些高级策略时，实际触发时机仍受它们影响。

云汇没有自己的语义压缩算法。窗口配置不等于已经适配所有中转的压缩接口；当前第三方共存通道的远程 `/responses/compact` 尚未接入，官方通道仍交给官方服务处理。

依据：[官方配置说明](https://developers.openai.com/codex/config-reference)、[客户端窗口与阈值计算](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/openai_models.rs#L573)。不同安装版本的实际行为以该版本为准。

验证包含 `test-model-context.mjs`、`test-client-model-context.mjs`、`test-model-context-ui.py` 和 `test-model-batch-context-ui.py`，并已接入 Windows / macOS CI。全部测试使用隔离配置，不修改真实客户端或请求付费模型。

最新 90% 联动实现及双平台验证见 [压缩阈值验证记录](AUTO-COMPACT-VALIDATION.json)。
